# TOEIC VOCA 개인 학습 앱 — 설계

작성일: 2026-08-27

## 목적

네이버 블로그 `ms_carrick` 카테고리 28("ETS토익보카 2022.12")의 DAY01~DAY30
단어장을 크롤링해 데이터로 보관하고, 모바일에서 오프라인으로 쓸 수 있는
개인용 학습 앱을 만든다. 판매·배포 목적 없음. 사용자 1명.

## 원칙

- 서버 없음. 빌드 도구 없음. 의존성 없음.
- 데이터(`words.json`)와 학습 기록(localStorage)을 완전히 분리한다.
  크롤링을 다시 돌려도 진도가 날아가지 않는다.
- 모바일 우선. 오프라인 동작이 부가 기능이 아니라 요구사항.

## 데이터 수집

출처는 로그인 없이 열리는 두 개의 공개 엔드포인트다.

| 용도 | 엔드포인트 |
|---|---|
| 목록 | `m.blog.naver.com/api/blogs/{blogId}/post-list?categoryNo=28` |
| 본문 | `m.blog.naver.com/PostView.naver?blogId=...&logNo=...` |

본문은 SmartEditor ONE 구조라 `<div class="se-main-container">` 안에 전부 들어있다.
div 깊이를 세어 컨테이너를 잘라내고, `<br>`/`</p>`/`</div>`를 줄바꿈으로 바꾼 뒤
태그를 걷어내면 아래와 같은 줄 목록이 남는다.

```
hold v. 들다, 잡다                    ← 표제어
A man is holding a piece of wood      ← 예문
남자가 나무 토막을 들고 있다            ← 해석
hold a booklet 책자를 들다             ← 연어
```

### 줄 분류 규칙

| 조건 | 판정 |
|---|---|
| 품사 마커(`n. v. a. ad. adv. adj. prep. conj. phr.`) 포함 + 한글 포함 | 새 표제어 |
| 한글 없음 | 영어 예문 |
| 한글로 시작 | 직전 예문의 해석 |
| 영문으로 시작 + 한글 포함 | 연어 |

DAY마다 포맷 편차가 있다. DAY01은 해석·연어까지 있고 DAY17은 표제어+예문만
있다. 위 규칙은 두 경우 모두를 커버한다.

한 표제어가 품사를 여러 개 갖는 경우가 있어(`access n. 초과, 초과량, 과잉 a. 초라한`)
뜻은 `senses` 배열로 받는다.

### 검증

파싱이 휴리스틱이므로 크롤러는 끝에 이상 항목 리포트를 출력한다.
예문 없는 단어, 미지의 품사, 빈 뜻, 분류 실패한 줄(orphan), DAY별 단어 수 편차.

원문에 오타가 있다(`access`↔`excess`, `기어`↔`기여`, `sceremony`).
크롤러는 원문을 그대로 보존한다. 수정은 데이터 레이어가 아니라 사람이 판단할 문제다.

## 데이터 스키마

`data/words.json`

```json
{
  "meta": { "title": "...", "crawledAt": "2026-08-27", "sourceUrl": "...",
            "dayCount": 30, "wordCount": 900 },
  "days": [{
    "day": 1, "title": "사진묘사 필수 어휘 (1)", "logNo": 223053465294,
    "url": "https://m.blog.naver.com/ms_carrick/223053465294",
    "words": [{
      "id": "d01-001",
      "headword": "hold",
      "senses": [{ "pos": "v.", "meaning": "들다, 잡다" }],
      "examples": [{ "en": "A man is holding a piece of wood",
                     "ko": "남자가 나무 토막을 들고 있다" }],
      "collocations": [{ "en": "hold a booklet", "ko": "책자를 들다" }]
    }]
  }]
}
```

`id`는 `d{day:02d}-{seq:03d}`로 고정한다. 학습 기록이 이 id로 단어를 참조하므로
재크롤링 시에도 안정적이어야 한다.

## 학습 기록 스키마

localStorage 키 `toeic-voca-progress`

```json
{
  "version": 1,
  "settings": { "direction": "mixed", "dailyLimit": 30 },
  "words": { "d01-001": { "box": 3, "due": "2026-08-31",
                          "correct": 5, "wrong": 1, "lastSeen": "2026-08-27" } },
  "days":  { "1": { "lastStudied": "2026-08-27" } }
}
```

900단어 × 약 100바이트 ≒ 90KB. localStorage 한도(5~10MB)의 1~2%.

## 간격 반복 (Leitner 5박스)

맞히면 박스 +1, 틀리면 박스 1로 되돌린다.

| 박스 | 다음 복습 |
|---|---|
| 1 | 1일 후 |
| 2 | 2일 후 |
| 3 | 4일 후 |
| 4 | 7일 후 |
| 5 | 15일 후 |

고전 Leitner는 2의 거듭제곱(1·2·4·8·16)을 쓴다. 8과 16 대신 7과 15로 둔 것은
일주일과 반달이라 달력으로 감이 잡히기 때문이고, 실질적인 차이는 없다.

SM-2(Anki)는 정답률에 따라 간격을 곱해 늘려서 5회차가 90일쯤 된다. 로직이 크게
복잡해지는 데다, 시험 날짜가 정해진 공부에서는 그렇게 긴 간격이 쓸모가 없다.
교체가 필요하면 `BOX_INTERVALS` 한 줄만 바꾸면 된다.

## 화면

| 화면 | 내용 |
|---|---|
| 홈 | 오늘 복습할 단어 수, DAY 30개 진행률, 전체 통계 |
| 플래시카드 | 탭하면 뒤집힘. `모름 / 애매 / 안다` 3버튼 |
| 목록 | DAY별 전체 목록, 뜻 가리기 토글, 검색 |
| 퀴즈 | 4지선다. 오답 선택지는 같은 DAY에서 추출 |
| 설정 | 방향 모드, 하루 분량, 진도 내보내기/불러오기, 초기화 |

방향 모드(영→한 / 한→영 / 혼합)는 전역 설정으로 플래시카드와 퀴즈에 함께 적용된다.

## 기기 간 동기화

하지 않는다. localStorage는 기기별로 격리된다.

단어 암기는 실질적으로 폰에서만 일어나므로 문제가 되지 않을 가능성이 크고,
대비책으로 설정 화면에 진도 내보내기/불러오기(JSON)를 둔다. 백업 역할도 겸한다.

GitHub API로 진도를 repo에 커밋하는 자동 동기화는 토큰을 클라이언트에 두어야 하고
Pages가 공개라 관리가 번거롭다. 실제 불편이 생기면 그때 검토한다.
