# 구현 계획

설계: `2026-08-27-design.md`

## 1단계 — 데이터 수집 (완료)

`crawl.py` 작성 후 전체 수집. 결과 `data/words.json` 611KB.

수집 과정에서 드러난 포맷 편차 세 가지를 파서가 흡수하도록 두 번 고쳤다.

| 편차 | 예 | 대응 |
|---|---|---|
| 품사 마커 없음 | `under ~아래에` (DAY26) | 마커를 선택 항목으로 |
| 마커에 점 없음 / 뒤에 붙음 | `malfunction n고장` (DAY18) | 영어부 끝의 마커를 분리 |
| 품사만 있는 줄 | `v. (언론) 보도, 취재` | 직전 표제어의 추가 뜻으로 병합 |

표제어와 연어를 가르는 것이 핵심 난제였다. 둘 다 "영어 + 한글" 형태다.
DAY별로 품사 마커 사용 여부를 먼저 판정하고(`is_rich_format`), 마커를 쓰는 DAY에서는
마커 없는 여러 단어짜리 줄을 연어로 본다. 어간 매칭만으로는 `clap`→`applaud`,
`perform`→`perfrom`(원문 오타) 같은 경우를 놓쳤다.

최종: 1591단어 / 30일, 분류 실패 5줄(전체의 0.05%).

## 2단계 — 앱 셸

- `docs/index.html` — 화면 5개를 한 문서에 담고 JS로 전환. 하단 탭바.
- `docs/style.css` — shadcn 디자인 언어를 순수 CSS로. CSS 변수 기반 라이트/다크.
- 이모지를 쓰지 않는다. 아이콘이 필요하면 인라인 SVG.

## 3단계 — 데이터 · 저장 계층 (`app.js` 상단)

- `words.json` 로드 → 단어 인덱스(`byId`) 구성
- `Progress` 모듈: localStorage 읽기/쓰기, 마이그레이션(`version`), 내보내기/불러오기
- `Scheduler` 모듈: Leitner 5박스. `dueWords()`, `grade(id, result)`

## 4단계 — 화면

순서대로 만들고 각 화면이 동작하는 것을 확인한 뒤 다음으로 넘어간다.

1. **목록** — 데이터가 제대로 보이는지 먼저 확인. 검색, DAY 필터, 뜻 가리기
2. **플래시카드** — 뒤집기, 3버튼 채점, 방향 모드 반영
3. **홈** — 오늘 복습 수, DAY 진행률, 통계
4. **퀴즈** — 4지선다, 오답 선택지는 같은 DAY에서, 결과 화면
5. **설정** — 방향, 하루 분량, 내보내기/불러오기/초기화

## 5단계 — PWA

- `manifest.json` — 이름, 색상, 아이콘(192/512), `display: standalone`
- `sw.js` — 셸과 `words.json`을 설치 시 캐시. cache-first.
- 아이콘은 파이썬으로 PNG를 직접 생성한다(외부 의존성 없이).

## 6단계 — 배포

## 검증

- 데이터: id 중복 없음, 예문 보유율, 복수 뜻 파싱 확인 (완료)
- 앱: 로컬 서버로 띄워 화면 전환·채점·저장·새로고침 후 진도 유지 확인
- PWA: 서비스워커 등록 확인, 오프라인 전환 후 동작 확인
